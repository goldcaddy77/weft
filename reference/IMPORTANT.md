# Code Review Findings

Last reviewed: 2026-04-09

Action items surfaced by code review. Items here are also tracked in the **"Competitive Parity & Gap Closure"** section of `reference/architecture.md` where they correspond to acceptance criteria. When an item ships, flip the box here and update the architecture doc in the same commit.

## Open Action Items

- [ ] **Tool effect log never cleaned up on workflow termination.** `src/core/engine.ts:#cleanupWorkflowStorage` sweeps `sig:`, `offload:`, `blob:`, and `shared:` prefixes but omits `tool-effect:`. Every completed workflow leaves its per-tool-call effect records in storage permanently, which accumulates linearly with tool-call volume over the engine's lifetime. Fix: add `tool-effect:${workflowId}:` to the `prefixes` array in `#cleanupWorkflowStorage` (it should be cleaned alongside other workflow-scoped scratch space, regardless of `includeOutputArtifacts`). Add a regression test that runs a workflow with ≥3 tool calls, completes it, and asserts `storage.scan('tool-effect:')` yields zero entries.

- [ ] **Constraints silently skipped in worker execution mode.** `src/core/engine.ts:#evaluateConstraints` short-circuits on `this.#inlineStrategy?.getContext(workflowId)` — when `workerExecution: true` the inline strategy is absent, so every registered constraint is silently ignored. The only warning lives in a JSDoc comment on `ConstraintDefinition.check` in `src/core/constraint.ts`. Fix (pick one): (a) throw at registration time when `engine.register(workflow, { constraints })` is called on a worker-mode engine so the failure is loud; (b) forward constraint evaluation to the worker via a `WorkerInboundMessage.evaluateConstraints` round trip; or (c) at minimum, emit a `console.warn` on `register()` for the combination. Option (a) is the smallest safe change.

- [ ] **Chaos fault classes do not match their names.** `src/testing/chaos.ts` treats `'transient'`, `'timeout'`, and `'error'` as three flavors of `throw new Error(...)` with different message prefixes. A `'timeout'` fault should model an actual timeout (e.g., a promise that never resolves until an `AbortSignal.timeout()` fires) so the mock exercises the timeout handler path; a `'transient'` fault should throw a retryable error subtype (so the retry policy kicks in); `'error'` should be non-retryable. As shipped, chaos tests all three classes look identical to the caller and cannot cover the distinct failure modes ReliabilityBench's four axes are meant to capture. Fix: split the switch in `withChaos` into three genuinely distinct behaviors and add tests that assert each class triggers its intended engine code path.

- [ ] **`canonicalize()` collision between `undefined` and literal string `"undefined"`.** `src/ai/tool-effect-log.ts` encodes `undefined` as the JSON string `'"undefined"'`. A tool input field whose value is the literal string `"undefined"` produces the same canonical form, which produces the same semantic hash, which lets one call shadow another in the effect log. Fix: use a non-JSON sentinel (e.g., the byte `\x00` followed by `undefined`, or simply omit undefined-valued keys from the canonical form entirely) and add a unit test that `computeSemanticHash({ a: undefined })` differs from `computeSemanticHash({ a: 'undefined' })`.

- [~] **Performance targets measured against spec** (2026-04-07): Re-measured after Item 3 optimizations (prepared-statement caching in `BunSQLiteStorage`, auto-id dedup-skip on the start path, completion-state-merge dedup, nesting-depth-map allocation skip, and a benchmark methodology fix for cold start). Findings:
  - **Workflow recovery**: spec `<1ms`, measured `~0.08ms` median → **meets spec** (12x headroom).
  - **Cold start (library mode)**: spec `<50ms`, measured `~0.14ms` median → **meets spec**.
  - **Cold start (binary mode)**: spec `<100ms`, measured `~36ms` median (warm-cache, 5-run median on Apple Silicon) → **meets spec**.
  - **Event dispatch**: spec `<100μs`, measured `~0.18μs` per dispatch → **meets spec** (500x headroom).
  - **Search attribute scan (100K workflows)**: spec `<1ms`, measured `~0.14ms` median → **meets spec** (in-memory SQLite only).
  - **Workflow starts**: spec `>50K/sec`, measured `~21K/sec` → **partially closed**, still 2.4x short. Remaining gap is dominated by the single SQLite WAL fsync per `start()` and the inline strategy's generator drive on the main thread; closing it further requires pipelining the start batch or moving to a binary checkpoint format.
  - **Activity completions**: spec `>30K/sec`, measured `~14K/sec` → **partially closed**, still 2.1x short. Remaining gap is dominated by the per-workflow scheduler cancel and `#cleanupTerminalWorkflow` deletes; coalescing them into the completion batch is the next lever.
  - **Memory per workflow**: spec `≤2KB`, measured `~6.8KB` in isolation and `~7.7-9.3KB` under full-suite pollution → **partially closed**, still 3-4x over. Closing the gap to 2KB requires architectural changes — releasing suspended generators between yields, or adopting a binary checkpoint format that lets the engine evict in-memory state on suspension.
