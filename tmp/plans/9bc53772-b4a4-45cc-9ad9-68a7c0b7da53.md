# Cover Aggregate Distinct-Key Cap

## Context

Task `9bc53772-b4a4-45cc-9ad9-68a7c0b7da53` asks for regression coverage around the existing `MAX_AGGREGATE_DISTINCT_KEYS` guard in `src/core/engine/aggregate.ts`. Open pull requests were reviewed first; none cover aggregate cap testing or `GET /v1/workflows/aggregate`.

The relevant implementation is already present:

- `src/core/aggregate-validation.ts` defines `MAX_AGGREGATE_DISTINCT_KEYS` and `AggregateDistinctKeyCapExceededError`.
- `src/core/engine/aggregate.ts` throws `AggregateDistinctKeyCapExceededError` once a new group would exceed the cap.
- `src/server/operations/aggregate-workflows.ts` maps that error to an `Unprocessable` operation fault and HTTP `400` for the REST route.

## Implementation Plan

1. Add a test fixture helper that writes encoded `WorkflowState` records directly to `MemoryStorage` under `KEYS.workflow(id)`.
   - Use unique workflow `type` values so `groupBy: 'type'` creates `MAX_AGGREGATE_DISTINCT_KEYS + 1` distinct groups.
   - Avoid `engine.start()` entirely so the test is fast and deterministic.
   - Use full `WorkflowState` objects with required fields: `id`, `type`, `status`, `input`, `version`, `createdAt`, and `updatedAt`.

2. Update `src/core/engine/aggregate.test.ts`.
   - Import `MAX_AGGREGATE_DISTINCT_KEYS`, `encode`, and `WorkflowState`.
   - Add a regression test asserting `engine.aggregate(undefined, { groupBy: 'type' })` rejects with `AggregateDistinctKeyCapExceededError`.
   - Assert the rejected error carries the exact `cap` value.

3. Update `src/server/operations/aggregate-workflows.test.ts`.
   - Reuse the direct-storage fixture shape against an `Engine` using `MemoryStorage`.
   - Call `GET /v1/workflows/aggregate?group_by=type`.
   - Assert the REST response status is `400` and the JSON error message contains the cap.

4. Public API and compatibility.
   - No public exports are added or removed.
   - No storage backend behavior changes; the tests use the existing storage interface and codec.
   - Browser compatibility is unaffected because this is test-only coverage.
